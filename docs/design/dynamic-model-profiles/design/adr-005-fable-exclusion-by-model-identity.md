# ADR-005: The Fable exclusion applies to the model's identity, not to one alias

Status: proposed with the design. Q-33 asks the person to confirm the reach.

## Context

- The exclusion exists only as prose in the proposal (section 14.3), which infers without verification that Fable is Claude Code's `fable` alias (A-78). The person answered "that alias only" (Q-7), then "no fable avalible." (Q-13) and "fable is bloked by company." (Q-24).
- In Claude Code the `best` alias resolves to the `fable` model where Fable is available; `fable` resolves to Fable 5.1 unless an environment variable moves it; Fable can be chosen by full ID (`claude-fable-5-1`, `claude-fable-5`) (A-88, A-90, A-134). In non-interactive `-p` mode a Fable request is billed to usage credits without asking (A-91). Safety-flagged requests on Fable are re-run on other Opus models (A-98).
- Cursor lists Fable 5.1 under its own name, attaches a data-retention approval requirement for Enterprise, Teams and Privacy Mode (A-125), and names Fable 5 in the Router's pool (A-155); an Enterprise admin block is the only documented control (A-131, I-11). The team's Router is enabled with the routed model Displayed (Q-30).
- The company enforces restrictions on all three clients (Q-23). Orqlet cannot observe them.

## Decision

1. **`excluded[]` entries match by alias name, by model-ID pattern and by family tag**, each with a reason and a source. The shipped seed carries one entry for Fable that matches the aliases `fable` and `best`, the IDs `claude-fable-*`, Cursor's Fable entries and the family tag `fable`.
   **Matching rule, used for every comparison of a model string** (an exclusion, an identity, a family, the same-model test; ADR-007 uses it too). *Identity:* the string is normalised by Unicode NFKC, case-folding, trimming, treating `-`, `_`, `.` and spaces as one separator, and removing a provider prefix from a closed list (`anthropic/`, `openai/`, `google/`, `xai/`) and any bracketed option list; two strings are the same identity when their normalised forms are equal, or when one is a route's `resolves_to` or `also_known_as` of the other. *Exclusion:* deliberately broader and fail-safe: the exclusion test runs on the raw NFKC and case-folded string, bracket contents included, **and** on the normalised form, and it matches when the token (for Fable, `fable`) occurs as a substring once separators are removed, so `Fable5`, `fable-5.1-xhigh` and `x[model=fable]` all match, or when the string equals a listed alias. It runs on requested, observed, route `name`, `resolves_to` and `also_known_as` strings, including the display text that a displayed Router model produces (Q-30), such as "Claude Fable 5.1". A suffix such as `-xhigh` (A-66) is not stripped by the rule; the spellings that clients report are listed as `also_known_as` in data. `excluded[]` ID patterns are `fnmatch`-style globs, the matcher the code already uses (`independence.py:34`), never regular expressions. A string that fails the `ModelRef` or record type is still tested for the exclusion on its raw NFKC string before it is refused or reported as `unmatched`. Two catalog entries that claim the same normalised `name` or `also_known_as` are an error, so a family cannot be steered by a duplicate. **A string that matches no catalog entry is unknown: never equal and never different.**
2. **The exclusion is checked in three independent places, and the renderers write only what the resolver returns.** An exclusion applies to entries in every state, `proposed` included.
   - The resolver rejects an excluded candidate with the reason `excluded` (ADR-001); a renderer receives only the resolver's output (ADR-003) and so cannot name an excluded model.
   - `orqlet validate model-policy` reports an error when an approved model, a route, a candidate, a fallback or an assignment matches an exclusion, **and when an `excluded[]` entry present at the base tree is missing from the file** (the base is an optional `--base` revision, defaulting to the merge base with the protected ref the person names, as `validate review` does), and compares the `model` value of every agent and skill file in the client folders, team-authored ones included, with the exclusion (ADR-003, Decision 8).
   - `orqlet validate review` treats a record whose requested or observed model matches an exclusion as invalid evidence: an error, and the independence class is I0 (ADR-007). Under Cursor Auto this is how a routed Fable would show, because the Router is configured to display the model (Q-30).
   **Where the exclusion list comes from.** `validate review` takes the exclusions as the **union of the policy at the base tree and the policy at the staged tree**, so one change cannot remove an exclusion and pass a record against its own edit. A policy file that is present but cannot be loaded is an error for every record that names a model and never falls back to `model_families`. **A deleted file is not "absent":** `orqlet upgrade` never recreates a deleted seeded file and `doctor` skips seeded files (`src/orqlet/domain/classify.py:72-73`, `src/orqlet/application/usecases/diagnose.py:82-83`), so a file that is missing from the staged tree but present at the base tree, or that has a seeded row in the lock, is treated as unloadable, and `validate model-policy` reports it as a deletion. Only a project where the file was never present gets the legacy rules, and its report says no exclusion list was available.
3. **The `best` alias is never rendered**, even though it is not named Fable, because it resolves to Fable where available (A-88).
4. **Organisation controls are not generated.** No managed-settings or admin export is produced (the proposal's 14.3 sentence on managed settings is not built); the company's own blocks (Q-23, Q-24) stay the company's.

## Consequences

- A project can add its own exclusions with the same mechanism (a model a vendor retires, a vendor the company rules out), without a code change.
- The exclusion reads wider than Q-7 literally says. It never rendered anything that Q-7 allowed, so a team that wants the alias-only reading loses nothing it was getting; Q-33 asks the person to confirm.
- **The exclusion is defence in depth behind the company's block (Q-24), not a replacement for it.** Orqlet cannot stop Cursor Auto from routing to Fable; it can only reject the evidence afterwards.
- It rests on data. A removed entry removes the exclusion from the staged policy; there is no built-in exclusion floor, because a vendor's model name does not belong in code (the closed table of provider prefixes and the list of key shapes are data tables of the domain and the loader, covered by tests, not exclusions). The protection is the union with the base tree's policy, the deletion rule above, the review of the edit (CODEOWNERS on the policy path, ADR-004) and the seed: the shipped Fable entry reappears in the pending diff when a release changes the shipped seed (`orqlet upgrade` proposes a diff only when the shipped seed differs from the lock's record, `classify.py:78`), and a test keeps it in the seed. Every one of these checks is a command that a person or an agent runs; the CI workflow runs none of them (A-44, Q-36), so they are "checked", not "enforced".
- Identity matching depends on the recorded model strings. A client that reports nothing (Codex, U-3) gives nothing to match; the exclusion then rests on the company's controls.
- Limits that Orqlet cannot close: a project-level client settings file that names Fable (outside the file scan); a run-time override on a role that leaves no record (the tester, inventory and trace roles); an environment variable that remaps an alias (`ANTHROPIC_DEFAULT_FABLE_MODEL` and the other family variables, A-90, A-92), which is why pins use exact IDs; and the non-interactive billing of a Fable request (A-91), which is a spend control of the company's.

## Rejected alternatives

- **Exclude the `fable` alias only.** It leaves `best` and every explicit ID as paths to the same model (I-4).
- **Generate managed settings that deny Fable** (`deniedModels`, a Cursor block). Orqlet renders no settings and does not hold the admin's authority; the company already enforces it (Q-23, Q-24).
- **Rely on the company's block alone.** Orqlet could not tell a record of a review that ran on Fable from any other, and a pin or alias could still be rendered by mistake.
