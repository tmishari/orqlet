# ADR-001: Write skill, agent and command front matter that a line reader and a YAML reader read the same, and test it

Status: accepted by the person on 2026-10-25, in conversation. No pull request was merged. Decision 2 was amended on 2026-10-25 after the P-1 reviews, to state the line-view choices and a narrower no-raise wording, and the person approved the amendment.

## Context

- On 2026-10-23 Cursor listed Orqlet's generated agents with the quote characters inside the name (`"orqlet-inventory"`) and rejected a call that used the plain name (AS-IS O-11). It also reported that the configured model `"inherit"` was blocked by the team's admin settings, and ran every subagent on another model (O-12). The files are valid YAML: `front_matter` writes every string quoted (`src/orqlet/adapters/render/emit.py:56-59`, `quote_all=True`).
- What is observed: Cursor, for agent files only. Whether removing the quotes also fixes `model` is not observed. What is not observed at all: Cursor for skills, commands and rules, and Claude Code and Codex for every file (AS-IS U-9).
- Harness² checks the front matter of the files that it generates with line regular expressions on the first 600 characters, without a YAML parser (AS-IS S-04). That shows the idea of a simple-reader check; it is not evidence about any client.
- Orqlet's release tests check descriptions, command names, read-only controls and byte-identical output (`tests/unit/render/test_skills.py`), but none compares what a line-oriented reader sees with what a YAML reader sees. Two tests pin the quoted forms of a skill and a role (`tests/unit/render/test_skills.py:272-273,319`); the tests of rule files and of a command whose description contains a colon pin forms that do not change (`tests/unit/render/test_rules_and_instructions.py:50`, `tests/unit/render/test_commands.py:42`).
- A scan of `tests/golden/` found 32 skill, agent and command Markdown files with front matter (28 `name`, 32 `description`, 10 `model` and 4 `tools` strings, plus booleans) and exactly one workflow-owned string that cannot be written plain: the `description` of `orqlet-research` contains `: ` (in all three clients). Cursor commands have no front matter (`src/orqlet/adapters/render/rules.py:64-68`).
- Rule files carry project text: `.mdc` files for Cursor and `.claude/rules/*.md` for Claude Code, with `description` built from a rule id and text, and `paths` or `globs` taken from standards packs (`src/orqlet/application/usecases/render_request.py:143-144`). Orqlet does not control that text, and whether the clients read quoted rule values literally is unobserved.
- Codex roles are TOML files without front matter (`src/orqlet/adapters/render/roles.py:41-46`); Codex skills are Markdown with front matter.

## Decision

1. **Emitter.** `front_matter` gets a keyword-only parameter `plain_when_safe: bool = False` (EC-3). When it is true, a string value is written without quotes if it is plain-safe, and with quotes exactly as today otherwise; booleans and integers are written as today. The renderers of skills, agent roles and commands pass `True`. The renderers of rule files do not, so their bytes do not change. A string is plain-safe when it starts with an ASCII letter; has only ASCII letters, digits, space and the characters `, . ; ( ) / _ + = - '` after that; does not end with a space or an apostrophe; and is not a YAML reserved word (`true false null yes no on off y n`, any case). This is an allow-list: it excludes non-ASCII text (so the escaping that `emit.py:20-21` does stays in force), everything that starts with a digit or a symbol (numbers, dates, `<<`, `~`, `.inf`), and every character that has a meaning in YAML. The predicate is private to `emit.py`. The public `yaml_scalar` and `yaml_document` keep their signatures and their behaviour.
2. **Domain.** A new pure module `orqlet.domain.front_matter` has two functions. `simple_front_matter(block)` returns the key and value pairs that a reader taking one `key: value` line at a time sees, keeping any quote characters as characters. `front_matter_differences(line_view, parsed)` compares that view with the parsed strict view and returns one message per key whose two values differ, per key present in one view only, and per key whose parsed value is not a one-line scalar. The string form of a parsed scalar is: a string as it is, `true` or `false` for a boolean, decimal text for an integer, `null` for none; any other type is a difference. `simple_front_matter` never raises for any text and `front_matter_differences` never raises for any mapping; a `parsed` value that is not a mapping is the caller's error. Messages name keys and never print values. Where the design was open, the line view makes these choices, and tests pin them: a key is letters, digits, `_`, `.` and `-`, starting with a letter, digit or `_`, at column 0; `key:` reads as the empty value; `key:value`, with no blank after the colon, is not a `key: value` line; when a key repeats, the last line wins; only a line feed ends a line, after `\r\n` has been read as `\n`, and blanks are spaces and tabs; a folded or block marker such as `>-` is read as its own text.
3. **Release test.** For every skill (`*/skills/*/SKILL.md`), agent (`*/agents/*.md`) and Claude Code command (`.claude/commands/*.md`) that the renderers produce for the three clients, the test splits the block with the existing `split_front_matter`, parses it with the existing strict loader, and asserts that the block exists, that it parses, and that `front_matter_differences` is empty. Every key is compared, including `tools`, `readonly` and `disable-model-invocation`, which carry the read-only and no-auto-invocation controls.
4. **Predicate tests.** For every string that the predicate accepts, the strict loader, PyYAML's default safe loader (which resolves YAML 1.1 types) and `simple_front_matter` return the same string, tested with the awkward strings of `tests/unit/render/test_emit.py` and a property test over arbitrary text. The emitter's existing round-trip test for `quote` stays.
5. **Source text.** The `description` of `orqlet-research` is reworded so that it contains no `: `. This is a change to protected workflow text of the kind that changes no gate and no contract, so under design §20.8 it is patch-level. The manifest is rebuilt and the version is bumped (ORQLET-DET-002); `doctor` reports an error when a digest changes at an unchanged version (ORQ-E161, `src/orqlet/application/usecases/diagnose.py:231-238`).
6. **Outside the check, as stated limits.** Rule files (`.mdc` and `.claude/rules/*.md`); Codex roles (TOML) and the Codex sidecar, which are pinned by string assertions in `tests/unit/render/test_skills.py`; any file that Orqlet does not generate.
7. **`orqlet doctor` is not changed.** For files that Orqlet generates, `doctor` already reports tampered or edited files and an available upgrade by hash (ORQ-E150, ORQ-W152, ORQ-W162), so the release test closes the defect before release and the existing checks carry the fix to projects. A `doctor` check for extension skills or hooks that Orqlet does not generate returns when such content is designed (no section of the proposal designs it yet; §12.7 covers standards-pack content only).

## Consequences

- A repeat of the quoting defect, or any later change that makes the two views disagree for a generated skill, agent or command, fails a test before release.
- 32 rendered Markdown files change bytes (quotes removed), and six more goldens change because their markers carry the workflow version (`AGENTS.md` for the three clients and three PR-template files). The golden files change once, on purpose (ORQLET-DET-001), the protected-set digest changes, and the two tests that pin the quoted forms of a skill and a role are rewritten, not dropped. After an upgrade, approved artifacts written against the old digest are reported stale (ORQ-W390 with a reason, `src/orqlet/application/usecases/gate_status.py:179-185`). The built code states no refresh path for a stale artifact; the plan must (considerations).
- Rule files do not change, so the project text that they carry stays quoted as today.
- The line view models one class of reader. It does not prove how Claude Code or Codex read the files, and Cursor's reading of skills and commands stays unobserved. The change relies on this: a string that passes the allow-list is read as the same string, by the predicate test, by the strict loader (the release oracle), by the default YAML 1.1 loader and by the line view, so no reader known to this design is worse off. A client that requires quotes is not known and not tested.
- A value that is not plain-safe stays quoted and fails the release test until the source text is reworded; for workflow-owned text that is the intended pressure.
- New code: one pure module with two functions, one keyword parameter and one private predicate in `emit.py`, one release test, one text edit.

## Rejected alternatives

- **Fix the emitter and add no check.** The defect returns silently on the next change.
- **Change `front_matter` for every caller.** Rule files carry project text; the predicate would meet strings that Orqlet does not control, and the clients' reading of quoted rule values is unobserved.
- **Check a few keys only.** The read-only and no-auto-invocation controls are other keys (`tools`, `readonly`, `disable-model-invocation`), written quoted today.
- **A deny-list predicate** (any text that has no special YAML character). It lets through non-ASCII line separators and strings that YAML 1.1 types as numbers, dates or merge keys.
- **Reimplement each client's front-matter parser in Orqlet.** Their behaviours are undocumented and would drift.
- **Run the clients headlessly in CI to read the names.** There is no verified headless path for Cursor (design §21.4).
- **Check in `orqlet doctor` now.** It adds a use case, new finding codes and an exit-code effect for files that the hash checks already cover.
- **Adopt the whole Harness² rule set.** Its other rules concern content that Orqlet's generated files do not have (ADR-005).
