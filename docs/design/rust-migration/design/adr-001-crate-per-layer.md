# ADR-001: One crate per layer, boundaries enforced by the compiler, Clippy and an arch check

## Context

The Python package has four layers whose import direction import-linter checks (A-4); the standards require inward imports, a pure domain and an application layer without file, process or network modules (ORQLET-ARCH-001, ORQLET-ARCH-002), and process creation only in the process adapter, Git only through GitRunner (ORQLET-SEC-001, A-16 to A-18). import-linter does not exist for Rust, and Q-2 removes it.

## Decision

1. A Cargo workspace at the repository root with `crates/orqlet-domain`, `crates/orqlet-application`, `crates/orqlet-adapters` and `crates/orqlet-cli` (binary `orqlet`), plus the unshipped `xtask`. The root `members` list names each crate by its literal path, so the Rust project scanner can follow it (ADR-007 decision 13).
2. `orqlet-domain` is `#![no_std]` with `alloc`, so its own code cannot name `std::fs`, `std::process`, `std::net`, `std::env` or `std::io`. It holds `CanonicalValue` and `digest_of`, the line-range hash, paths, the Version type, the output filters (ADR-007 decision 15), findings, the change plan, the glob matcher and the UTC timestamp formatter (ADR-003). Its unit tests may declare `extern crate std` under `cfg(test)`.
3. `crates/orqlet-application/clippy.toml` sets `disallowed-types` and `disallowed-methods` for: the types and functions of `std::fs`, `std::process`, `std::net` and `std::env`, each written as a fully qualified path (`clippy-disallowed-types.md` items 3 and 4); `std::os::unix::fs` and `std::os::windows::fs`; the file-system methods of `std::path::Path` (`exists`, `try_exists`, `metadata`, `symlink_metadata`, `read_dir`, `read_link`, `canonicalize`, `is_file`, `is_dir`, `is_symlink`); and `std::io::stdin`, `stdout` and `stderr`. The crate root denies the Clippy lints `print_stdout` and `print_stderr` by attribute, which leaves the workspace lint table alone. Each crate's `clippy.toml` also carries the parser entry points of ADR-007 decision 7 for each parser crate it depends on directly, so no listed path fails to resolve; a crate that gains a parser dependency gains its entries in the same change. The list is the boundary that the check enforces. It sits under the security globs, and adding to it or removing from it is a reviewed change.
4. The process module is a private child of the Git module of `orqlet-adapters`, so the compiler stops any other module from starting a process (ADR-007 decision 1). `orqlet-adapters` and `orqlet-cli` disallow `std::process::Command` in their `clippy.toml`; only the process module carries an `allow` with a reason.
5. Integration tests under `crates/*/tests/` and the xtask may use file, process and environment APIs and the parser entry points (the built `orqlet`, `git`, `cargo metadata`, fixtures, JSON envelopes and temporary folders), each file under one scoped `allow` with a reason. Unit tests inside the application crate embed their inputs. Shipped code under `crates/*/src/` gets no such allow, except the process and documents modules (ADR-007).
6. `cargo run -p xtask -- arch` reads `cargo metadata` and checks every direct dependency of each kind (normal, dev and build) of each workspace crate. It fails when a crate depends on a workspace crate outside its allowed edges: domain none; application domain; adapters application and domain; cli all three; xtask application and domain. It also fails on a third-party crate missing from that crate's own allow-list in `xtask/src/arch.rs`. The lists are exact per crate, not cumulative: domain allows `sha2`, `unicode-normalization` and the Unicode category crate (ADR-007 decision 14), all without default features; application allows `serde`, `serde_json`, `schemars`, `similar` and `regex`; adapters allows `serde`, `serde_json`, `serde-saphyr`, `toml`, `include_dir`, `dirs`, `uuid` (feature `v4` only, Q-17) and `libc` (Unix only); cli allows `clap`, `serde` and `serde_json`; xtask allows `serde`, `serde_json` and `schemars`. No crate has a dev-dependency beyond its list, so tests use the standard library and the crates on their crate's list. The xtask also reads the enabled features from `cargo metadata` and fails when `uuid` has a feature other than `v4`, or a domain crate has its default features. Transitive crates are not checked by the xtask. They change only through `Cargo.lock`, which is under the security globs. Adding a crate to a list is a reviewed change to that file.
7. Unsafe code is forbidden once for the whole workspace: `[workspace.lints.rust] unsafe_code = "forbid"` in the root `Cargo.toml`, with `lints.workspace = true` in each crate.
8. The client adapters (Claude Code, Codex, Cursor) stay modules of `orqlet-adapters`, and a reviewer checks that they are independent. The empty Copilot adapter, the user-scope writer with its journal, and the install and uninstall presenter are not ported (Q-8). The `copilot` value of `hook --client` stays, because the hook command is wired (C-2, BC-1). The wired readers of user-scope data in `status` and the hook (`src/orqlet/application/usecases/status.py` lines 224-243, `hook_event.py` lines 242-251) are ported and report the data as missing when no 0.5.2 install wrote it.

## Consequences

- The layer rule is checked on every build (`no_std`, Cargo), and by Clippy and `xtask arch` before each pull request.
- `#![no_std]` binds the domain's own code; the purity of its dependencies rests on the allow-list, which a reviewer approves.
- Python's `casefold` has no equivalent in `alloc`, so the path comparison key becomes NFC plus `to_lowercase` (A-15); characters whose full case folding differs from lower-casing, such as the German sharp s, compare differently from 0.5.2, which Q-5 allows. The Unicode version behind NFC follows the pinned `unicode-normalization` crate instead of the Python runtime (U-8).
- Whether `sha2`, `unicode-normalization` and the Unicode category crate build without the standard library was not looked up in this design; if one does not, the plan stops and asks.
- Code inside the application crate cannot reach the file system, processes or standard streams by a listed path. Anything not on the list, such as a newly added standard-library API, is caught only when a reviewer reads the change.
- Clippy reads `clippy.toml` from `CLIPPY_CONF_DIR` when that variable is set (`clippy-disallowed-types.md` item 1), so the QA-001 checks run without it.
- Four manifests to maintain instead of one; shared versions live in `[workspace.dependencies]`.
- Client independence loses its deterministic check (ORQLET-ARCH-003 becomes a review rule, ADR-006).

## Rejected alternatives

- One crate with modules and `pub(crate)` visibility: Rust has no inward-only import check inside a crate, so the layer rule would rest on review alone.
- One crate per client adapter as well: keeps ARCH-003 deterministic, but adds four crates for modules that are each a few hundred lines; rejected as cost without a stated need.
- A text scan for `use std::fs` in xtask: misses fully qualified paths and macros that Clippy's type resolution catches.
- `cargo-deny` for the dependency allow-list: a further tool to install and pin, for a check that `cargo metadata` and a short xtask cover.
